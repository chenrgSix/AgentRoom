# AgentRoom v0.3.0-rc.5

This release candidate fixes Windows Desktop first-time enrollment and makes the
single-host central HTTPS profile work predictably on a LAN at port 9443.

## Highlights

- Fixes Windows Desktop enrollment requests whose Wails/WebView2 transport
  preserves the JSON body while reporting a zero content length. The Bridge now
  decodes the body instead of validating an empty `serverUrl`.
- Adds a focused regression using `https://192.168.1.132:9443` with pinned
  SHA-256 trust, matching the failing Windows setup path.
- Changes the Compose HTTPS default from port 443 to configurable port 9443 and
  keeps HTTP redirects aligned with the exact configured public origin.
- Configures Caddy with the central host as its default SNI so LAN clients that
  connect to the server by IP can receive the intended certificate.
- Restores `TRADEMARKS.md` to the Docker build context so the central Server
  image retains all required license and policy assets.

## Upgrade and Compatibility Notes

- Upgrade the central Server, Caddy profile, and Windows Bridge from this tag.
  This candidate has no new central database migration.
- Existing deployments may keep another HTTPS port by setting
  `AGENT_ROOM_HTTPS_PORT` and matching it exactly in
  `AGENT_ROOM_PUBLIC_ORIGIN`.
- The default LAN endpoint is `https://HOST:9443`. Server port 3000 remains
  private to the Compose network.
- A Windows Bridge using `v0.3.0-rc.4` must be upgraded to this candidate before
  retrying first-time Desktop enrollment. The central service alone cannot fix
  the local request-decoding defect.
- Private Caddy certificates still require either trusted-root installation or
  explicit leaf-certificate pinning on the Bridge. A leaf pin must be refreshed
  whenever Caddy renews that certificate.
- The Windows Desktop package still targets Windows 10 or newer on amd64/x64,
  requires the system WebView2 Runtime, and remains unsigned.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup after migration.

## Artifacts

The Release workflow publishes five portable CLI archives, two native macOS
Desktop ZIPs, one Windows Desktop portable ZIP, one Windows per-user installer,
`SHA256SUMS`, `LICENSE`, `NOTICE`, `COMMERCIAL-LICENSE.md`, and `TRADEMARKS.md`.
The committed verifier requires exactly 14 assets and checks their names,
checksums, archive paths, architectures, embedded versions, GUI and installer
metadata, launchers, and license files before and after upload.
