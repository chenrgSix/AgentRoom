# AgentRoom v0.3.0-rc.2

This release candidate turns the local Bridge into a clearer desktop product,
adds general in-app usage guidance, and lets each Codex Agent choose how to
handle a native session held by another local client.

## Highlights

- Reorganizes the native Bridge around Agent-first Overview, Local Agents, and
  Settings pages with clearer connection recovery and safer technical details.
- Replaces the narrow Codex-only help entry with an embedded AgentRoom Bridge
  usage guide that covers ordinary operation before Task, Run, native session,
  recovery, and separate App Server behavior.
- Adds a per-Agent Codex session-conflict policy. The recommended
  `preserve_and_retry` option keeps the existing binding for later retry, while
  explicit `start_new` can continue in a fresh session after a recognized
  active-writer conflict.
- Shows the selected conflict policy on local Agent cards and beside the Codex
  sandbox so the continuity tradeoff is visible before saving.
- Adds the same bounded choice to terminal enrollment through
  `--codex-session-conflict-policy`.

## Upgrade and Compatibility Notes

- Upgrade the central Server, Web UI, contracts, and Bridge from the same tag.
  This candidate has no new central database migration.
- Local Bridge configuration advances to `schemaVersion: 3`. Older files
  migrate in memory with `preserve_and_retry`; the next explicit save persists
  the selected policy.
- `start_new` applies only when Codex reports the recognized active-writer
  conflict. Bridge keeps the old provider Thread and local binding until Codex
  accepts a replacement, then replays the full current Task bootstrap and
  reports the session as recreated.
- Unknown resume rejection still preserves the binding and fails closed as
  `CODEX_SESSION_RESUME_FAILED`; the policy cannot broaden filesystem, tool,
  network, or approval authority.
- Codex Desktop and AgentRoom Bridge still run separate App Server processes.
  This release does not claim an official Desktop daemon attachment API.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup after migration.
- macOS Desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
Desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

Candidate admission requires exact-source contract validation and generation,
production builds, Server, Web, contract, Go, Desktop, deterministic
cross-process E2E, documentation, Compose, release-script, packaging, and
clean-download checks. Credentialed Codex and Pi execution remains an explicit
live test and is not part of ordinary CI.

## Remaining Gates

- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- Packages remain unsigned, unnotarized, and manual-update-only.
- `v0.2.0` remains the stable Latest release while this candidate is evaluated.
