# AgentRoom v0.2.0

AgentRoom v0.2.0 is the first stable trusted-small-Team baseline. It turns
Rooms into durable multi-Agent workspaces where managed and manual Agents can
continue Tasks, share bounded context and reviewed Memory, exchange verified
Artifact content, and recover across process or connection failures.

## Highlights

- Adds first-class Task identity across Messages, Runs, handoffs, Discussions,
  clarifications, Runtime Sessions, context, Memory, and result evidence.
- Resumes managed Codex and Pi work through Task-scoped logical Sessions while
  delivering only acknowledged Room, Task, Artifact, and Memory deltas.
- Maintains recoverable rolling Room checkpoints and lets Members review
  automatically proposed long-term Memory before promotion.
- Carries structured commit, branch, file, patch, test, and document evidence
  through a strict consumed cursor with immutable provenance.
- Publishes content-bearing canonical Task Artifacts through an accepted
  Run-scoped Workspace lease, durable content-addressed Blob sealing, and one
  transactional Artifact binding.
- Pins Artifact content into later Run deliveries, materializes it in
  Bridge-owned read-only staging, and exposes only verified logical aliases to
  local Runtimes without writing into their configured Workspaces.
- Records immutable derivation, review, and verification lineage so an Agent
  can consume Artifact A and publish independently verifiable Artifact B.
- Adds bounded escaped previews for Patch, Markdown, and JSON Artifact content
  while preserving Team authorization and local-path secrecy.

## Upgrade and Compatibility Notes

- Upgrade the central service, Web UI, and Bridge from the same tag. The Server
  applies migrations 0023 through 0038 for Runtime activity, Tasks, context,
  result evidence, clarification, rolling Memory, Workspace leases, Blob
  publication, Artifact content binding, and lineage.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup rather than opening a migrated database with an older build.
- Artifact publication and materialization capabilities are additive. Older
  Bridges remain able to participate in reference-only collaboration but do
  not receive content-bearing Artifact delivery.
- Materialized files remain outside the configured Workspace, are read-only
  and non-executable, and are treated as untrusted input even after digest
  verification. Applying their contents to a Workspace remains an explicit
  local Runtime or user decision.
- macOS desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

Stable admission requires the exact tagged source to pass main CI, including
contract validation and generation, production builds, Server, Web, contract,
Go, Desktop, deterministic cross-process and two-Bridge Artifact recovery
tests, maintained Markdown lint, Compose validation, and release-script checks.
The tag-pinned no-clobber Release workflow must then build and verify all 11
assets, followed by an independent clean public download using the same
committed verifier.

Local preflight passed 7 schemas with 56 fixtures, 128 Server tests, 24 Web
tests, 4 contract tests, production builds, deterministic real-process E2E,
ordinary Bridge and Go contract tests/vet, focused race coverage, native
Desktop tests/vet/build, Compose and release-script validation, and local
darwin/arm64 CLI and Desktop packaging with the embedded `v0.2.0` version. An
audit against the official npm registry reported zero vulnerabilities. The
credentialed live Runtime test remained explicitly skipped as designed.

## Supported Scope and Remaining Evidence

This stable version is the supported baseline for trusted small Teams. It is
not a claim of internet-scale identity, high availability, signed distribution,
automatic updates, or universal production readiness.

- `BRG-013` remains active until a real macOS logout/login or restart proves
  exactly one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` remains ready until two physical machines produce reviewed online
  and offline/reconnect Codex evidence.
- Credentialed Codex and Pi execution remains an explicit live test and is not
  part of ordinary CI.

These are visible post-release physical-environment and operational acceptance
items, not evidence silently treated as complete by the stable release.
