# AgentRoom v0.2.0-rc.3

This release candidate stabilizes the Room experience and isolates managed
Agent execution so one local Runtime cannot accidentally receive overlapping
Runs.

## Highlights

- Synchronizes Room messages incrementally and recovers missed tails without
  replacing the active composer state.
- Shows bounded, redacted Runtime failure details and adds an explicit Bridge
  self-test for Codex, Pi, and Generic presets.
- Migrates legacy Runtime presets while preserving user configuration and
  preventing credentials or raw stderr from entering diagnostics.
- Runs different managed Agents concurrently while enforcing FIFO concurrency
  one for each individual Agent.
- Accepts durable inbox deliveries before scheduling, deduplicates retries, and
  supports deterministic cancellation while a Run is still queued.
- Preserves explicit recovery behavior across Bridge disconnects and reports an
  unknown outcome instead of silently replaying uncertain Runtime work.

## Upgrade and Compatibility Notes

- Upgrade the central service and Bridge from the same tag. Room incremental
  synchronization requires the matching Server and Web projection behavior.
- Existing Bridge configuration is migrated when loaded. Back up the Bridge
  configuration before downgrading to an older candidate.
- Queued Runs now wait behind work for the same Agent. Runs for different Agents
  remain eligible for parallel execution.
- macOS desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

The tagged source must pass schema validation, Node builds and tests,
deterministic cross-process E2E, maintained Markdown lint, ordinary and
Desktop-tagged Bridge tests/vet, race tests for the execution gate, and native
desktop compilation. Credentialed local Codex and Pi execution remains an
explicit live test and is not part of ordinary CI.

## Remaining Gates

- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- This candidate targets trusted small teams, not an internet-scale identity or
  high-availability service.
