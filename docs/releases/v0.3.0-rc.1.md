# AgentRoom v0.3.0-rc.1

This release candidate makes local Bridge ownership and recovery easier to
understand, adds explicit local privacy controls, and projects a bounded Agent
file-access summary into the central roster.

## Highlights

- Adds persistent Bridge pairing guidance and an explicit re-enrollment flow
  that drains active work and preserves the previous identity and Runtime
  configuration if replacement fails.
- Requires local, per-endpoint consent before Runtime reasoning summaries can
  leave the Device. Disabled consent retains contiguous recovery without
  publishing summary content.
- Discovers Codex and Pi executables from bounded local sources and explains
  missing Runtime installations without silently changing saved configuration.
- Classifies retryable Codex Task Session ownership and resume failures without
  forking a replacement session or exposing provider-native error detail.
- Adds an embedded Codex Task Session guide that distinguishes Room Messages,
  Runs, AgentRoom Tasks, native Codex sessions, and the current separate App
  Server processes.
- Adds an opt-in composer preference that visibly retains exact Agent Mention
  identities across follow-ups without persisting recipient IDs or drafts.
- Shows read-only, Workspace-write, local-policy, or unreported file access on
  central Agent cards using only the authenticated safe Runtime projection.

## Upgrade and Compatibility Notes

- Upgrade the central Server, Web UI, contracts, and Bridge from the same tag.
  Migration 0039 adds the nullable safe Runtime policy projection to Agents.
- `runtimePolicy.filesystemAccess` is additive and optional. Older Bridges
  remain accepted and are shown as **not reported**; omission clears any stale
  projection instead of retaining a previous policy.
- The projection never contains Workspace paths, commands, tools, environment
  variables, Provider details, accounts, or credentials. Unknown or extended
  policy objects are rejected at the Bridge boundary.
- Codex Desktop and AgentRoom Bridge still own separate App Server processes.
  The session guide documents this current boundary; the candidate does not
  claim an official Desktop daemon attachment API.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup after migration.
- macOS desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

Candidate admission requires exact-source contract validation and generation,
production builds, Server, Web, contract, Go, Desktop, deterministic
cross-process E2E, documentation, Compose, release-script, packaging, and
clean-download checks. Credentialed Codex and Pi execution remains an explicit
live test and is not part of ordinary CI.

## Remaining Gates

- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- Packages remain unsigned, unnotarized, and manual-update-only.
- This candidate targets trusted small Teams, not internet-scale identity,
  high availability, or universal production readiness.
