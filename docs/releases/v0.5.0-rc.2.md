# ConveneWire v0.5.0-rc.2

ConveneWire v0.5.0-rc.2 is a prerelease candidate for the completed Governed
Software-Team Execution Core. It supersedes the unpublished, zero-asset
v0.5.0-rc.1 candidate, whose final Server image failed closed before
application readiness. Stable Latest remains v0.4.2 while this candidate is
evaluated.

## Highlights Since v0.4.2

- Discussions can produce structured Plan proposals; assigned Tech Lead Agents
  can propose or revise them, and humans review and authorize exact revisions.
- A deterministic scheduler executes approved DAGs with bounded capacity,
  explicit manual/supervised/automatic modes, durable fairness and controlled
  generation-2 retry.
- Local governed Runs use owner-approved Bridge profiles, repository grants and
  isolated worktrees. Candidate output is independently verified before exact-
  target compare-and-set integration.
- Accepted Result, verified output and integrated commit gates advance only
  through retained SourceEvidence, GateProof and explicit EvidenceAdoption
  facts. Agent text alone is never verification authority.
- Plans can be superseded through immutable next-revision candidates, exact
  local evidence carry-forward and bounded one-shot Tech Lead delegation.
- Focused Discussions support opt-in read-only quorum sealing and retain late
  responses as separate content-free supplemental evidence.
- The Web UI exposes Plan creation/approval, proof and recovery decisions,
  supersession/carry/delegation controls and quorum audit facts without taking
  Server or Agent authority.
- All registered tests and disposable previews share one owned run root with
  invocation-scoped Go/npm caches and physical cleanup across success, failure,
  startup error, timeout, cancellation and parallel execution.

## Repository and Remote Provider Boundary

ConveneWire does not take over your Git repository or Git credentials.
Repository paths, Git remotes, Git/SSH credentials, fetch/pull/push, worktrees
and Git command execution remain under the local Client/Bridge and machine
Owner. Central governs Plans, scheduling, bounded authorization,
Evidence/Proof/Adoption and operation receipts.

Remote commit, CI and input-attestation support remains an optional extension.
The default installation has no Remote Provider credential and performs no
active provider access. This release does not add GitHub/GitLab adapters, PRs,
webhooks, push, remote merge or provider-credential Web controls.

## Upgrade and Compatibility

- Back up Central with the documented online backup procedure before upgrading
  and retain the v0.4.2 release, database backup and required operator secrets.
- v0.4.2 contains migrations through `0055`; this candidate migrates forward
  through `0086`. Rollback requires the pre-upgrade database and matching old
  binaries. Do not run v0.4.2 binaries against the upgraded database.
- The Bridge protocol remains `1.0`, and existing Device/Agent identities are
  preserved. Install the candidate Central, Web and Bridge together to use the
  complete governed-execution workflow.
- Canonical `convenewire://` and bounded legacy `agentroom://` desktop handlers
  remain supported.
- macOS packages require macOS 12.0 or later. Windows Desktop requires WebView2.
  Packages are unsigned, macOS is not notarized, and updates remain manual.

## Verification and Limits

Publication requires exact-tag green CI, the complete protected Release
workflow, native Windows v0.4.2-to-candidate upgrade verification, both Central
OCI clean-daemon executions, all 22 assets verified before and after upload,
and an independent credential-free public download verification.

This candidate does not claim macOS login-restart acceptance, exhaustive
Hosted-Agent production browser acceptance, live-provider admission, multiple
physical execution machines, signed distribution, automatic updates or a
production deployment. `BRG-013`, `WEB-050` and `QA-038` remain open.
