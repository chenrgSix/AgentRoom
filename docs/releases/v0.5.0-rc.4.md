# ConveneWire v0.5.0-rc.4

ConveneWire v0.5.0-rc.4 is a transition prerelease for the completed Governed
Software-Team Execution Core. It supersedes v0.5.0-rc.3 for evaluation and
adds a safer, more practical way to prepare another Windows browser for a
private-CA Central. Stable Latest remains v0.4.2.

## What Changed Since v0.5.0-rc.3

- An already paired private-scoped Bridge/Desktop now offers **Prepare another
  Windows browser** in its local Console.
- The assistant produces a self-contained PowerShell command from the exact
  public CA certificate already authenticated by that Bridge, so the Owner no
  longer needs to locate and transfer a certificate file manually.
- The command verifies the complete SHA-256 certificate digest in memory and
  on its randomized temporary file before installing only into the current
  Windows user's Root store. It removes only that owned temporary file in all
  exit paths.
- The UI shows the complete fingerprint, persistent-trust warning, browser
  restart instructions and an exact removal command. Re-pairing, Central
  changes, trust-epoch changes and CA changes invalidate stale commands.
- Opening or copying the assistant is local: it creates no room-entry ticket,
  performs no network request and contains no private key, Device/Server token,
  repository data or Runtime configuration.

Browser trust remains a deliberate Windows-user action. ConveneWire does not
silently modify the operating-system trust store. Once the same CA is installed
for that Windows user, ordinary ConveneWire, Chrome and Windows updates do not
require reinstalling it. A different machine/user or a rotated Central CA does.

## Inherited v0.5.0 Candidate Scope

- Discussion finalization, Tech Lead Plan proposal/revision and exact human
  approval feed a deterministic execution DAG.
- Owner-approved Bridge profiles and repository grants fence governed Runtime,
  isolated worktrees, independent verification and exact-target integration.
- SourceEvidence, GateProof and explicit EvidenceAdoption—not Agent text—grant
  accepted, verified and integrated dependency authority.
- Manual, supervised and automatic scheduler modes, generation-2 retry,
  bounded capacity, Plan supersession, evidence carry-forward and focused
  read-only quorum are included.
- The Web UI exposes Plan, proof, recovery, supersession, delegation and quorum
  controls without taking Agent, repository or local-machine authority.
- Test runners use owned run roots and invocation-scoped Go/npm caches with
  physical cleanup checks across success, failure, timeout, cancellation and
  parallel execution.

## Repository And Remote Provider Boundary

ConveneWire does not take over your Git repository or Git credentials.
Repository paths, Git remotes, Git/SSH credentials, fetch/pull/push, worktrees
and Git command execution remain under the local Client/Bridge and machine
Owner. Central governs Plans, scheduling, bounded authorization,
Evidence/Proof/Adoption and operation receipts.

Remote commit, CI and input-attestation support remains an optional extension.
The default installation has no Remote Provider credential and performs no
active provider access. This release does not add GitHub/GitLab adapters, PRs,
webhooks, push, remote merge or provider-credential Web controls.

## Upgrade And Compatibility

- Back up Central with the documented online backup procedure before upgrading
  and retain the v0.4.2 release, database backup and required operator secrets.
- v0.4.2 contains migrations through `0055`; this candidate migrates through
  `0086`. Rollback requires the pre-upgrade database and matching old binaries.
  Never run v0.4.2 binaries against the upgraded database.
- Bridge protocol remains `1.0`, and existing Device/Agent identities are
  preserved. Install Central, Web and Bridge from the same candidate.
- Canonical `convenewire://` and bounded legacy `agentroom://` handlers remain
  supported.
- macOS packages require macOS 12.0 or later. Windows Desktop requires
  WebView2. Packages are unsigned, macOS is not notarized, and updates remain
  manual.

## Verification And Limits

Publication requires exact-source green CI, the complete protected Release
workflow, native Windows v0.4.2-to-candidate upgrade verification, both Central
OCI clean-daemon executions, all 22 assets verified before and after upload,
and an independent credential-free public download verification.

This candidate does not claim physical multi-machine execution, native manual
trust-command acceptance beyond the packaged Windows regressions, macOS
login-restart acceptance, exhaustive Hosted Agent production-browser states,
live-provider admission, signed distribution, automatic updates or production
deployment. `BRG-013`, `WEB-050`, `QA-038` and stable task `QA-060` remain
separate.
