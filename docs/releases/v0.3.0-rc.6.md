# AgentRoom v0.3.0-rc.6

This release candidate lets an authenticated owner create a managed Agent on
one of their online Bridges after proving local authority with a short
Bridge-issued management code.

## Highlights

- Adds Bridge-local provisioning modes: disabled, reusable fixed 8-digit code,
  or a rotating 6-digit code that refreshes every five minutes.
- Adds a central Web flow that selects only the current Member's online,
  provisioning-capable Devices and managed Agent templates, then submits the
  management code without retaining it in browser or Server history.
- Adds durable provisioning requests with owner, Team, Device, template, and
  reserved Agent identity checks across HTTP, WebSocket delivery, Bridge-local
  authorization, and Agent Registry publication.
- Recovers ambiguous delivery, lost acceptance results, Server restart, and
  local configuration failure by retrying the same request and reserved Agent
  identity where safe.
- Rejects unsupported older Bridges before request persistence and advertises
  provisioning capability only when the Bridge has an active local handler.

## Upgrade and Compatibility Notes

- Upgrade the central Server and Web together. Migration 0040 creates the
  durable Agent provisioning request table and runs through the normal startup
  migration path.
- Upgrade each Bridge before using central Agent creation. Older Bridges remain
  valid for existing managed Runs, but they do not advertise provisioning
  support and are not selectable for this flow.
- Existing local Agent configuration remains authoritative. The central service
  can request creation only from an existing online managed template, while the
  Bridge validates the code, template identity, active-work fence, reserved
  Agent identity, and atomic local configuration replacement.
- Fixed 8-digit codes are reusable and intended for trusted LAN deployments.
  Rotating 6-digit codes are the safer choice when the Bridge is reachable from
  a less trusted network.
- This feature uses the existing trusted-Team Member identity and Device
  ownership model; it does not add public account federation or remove local
  Bridge consent.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup after migration.

## Security Boundary

The management code is a transient authorization proof. The central Server
does not persist it, return it from request history, or include it in durable
delivery state. The Bridge stores only the selected local mode and verifier
material, applies constant-time verification and attempt throttling, and never
returns local Runtime configuration, Workspace paths, credentials, provider
details, or permissions to the central service.

The Release workflow publishes five portable CLI archives, two native macOS
Desktop ZIPs, one Windows Desktop portable ZIP, one Windows per-user installer,

checksums, archive paths, architectures, embedded versions, GUI and installer
metadata, launchers, and license files before and after upload.

  two physical machines.
