# ConveneWire v0.4.1

ConveneWire v0.4.1 is the stable post-v0.4.0 hardening release for trusted
small Teams. It improves configured-client pairing, transactional Run recovery,
Runtime process ownership, deployment authority, release identity, privacy and
runtime-schema enforcement without changing the released protocol 1.0
compatibility boundary.

## Highlights

- Adds a direct Device-pairing link entry to an already configured Bridge
  client, so re-pairing no longer depends on opening the system protocol handler
  through **Win+R**. The existing stopped-and-drained identity replacement
  boundary still applies.
- Makes Message-to-Run allocation and reply projection transactionally
  recoverable across Server crashes, and persists one durable managed-Run
  cancellation intent through reconnect, restart and response loss.
- Binds Device credentials to their authenticated Central origin, enforces one
  Bridge state owner, and uses a Windows Job Object to terminate the bounded
  Runtime parent/child/grandchild process tree.
- Enforces authoritative generated Bridge schemas before business parsing,
  blocks implicit remote message images, and replaces synchronous polling
  amplification with event-driven waits.
- Serializes Central lifecycle mutation authority and distributes one immutable,
  digest-bound Central image pair per Release with clean-daemon execution,
  SBOM and provenance verification.
- Binds every Release job, native package and Central archive to one exact full-
  CI commit; Windows upgrade verification compares installed, staging and
  portable-ZIP executable digests while preserving Owner state.

## Upgrade and compatibility notes

- Upgrade Central, Web, contracts, controller and Bridge from the same tag.
  Back up Central first and retain the matching rollback package and database
  backup.
- The protected Windows workflow installs stable `v0.4.0`, upgrades in place to
  `v0.4.1`, verifies both protocol handlers and preserved Owner configuration,
  Agent identity and durable inbox state, then uninstalls without deleting that
  state.
- Existing Device credentials remain valid only for their paired Central
  origin. Moving to a different origin requires the supported scoped-private
  hostname migration or explicit re-pairing; credentials are never sent to an
  unbound endpoint.
- New Device links use `convenewire://`; `agentroom://` remains accepted only as
  a bounded compatibility handler for existing installs and links.
- macOS and Windows Desktop packages remain unsigned, macOS is not notarized,
  and updates remain manual. Verify `SHA256SUMS` before executing a download;
  never disable TLS or operating-system security globally.

## Physical acceptance boundary

The reviewed
[schema-v4 record](../acceptance/evidence/qa-002-20260830-schema-v4.md) binds the
exact `v0.4.1-qa035.1` candidate source to distinct physical macOS Central and
Windows Bridge hosts, current authenticated build identity, canonical pairing,
scoped private trust, Runtime self-test, same-Device offline/reconnect and
online Runs, bounded metrics and a human `PASS` receipt. Changes between that
candidate and the stable tag are documentation only.

That record admits the product source; it is not rewritten as execution of the
separately versioned stable binaries. Native stable-package construction,
upgrade and artifact identity are owned by the exact-tag Release workflow.

## Supported scope

The stable scope is trusted small Teams. It does not claim public Internet-scale
identity, high availability, signed/notarized distribution, automatic updates,
or universal environment certification.
