# ConveneWire v0.4.2

ConveneWire v0.4.2 is the stable update for trusted small Teams, adding optional
Central Hosted Agents, product experience improvements and audited recovery and
desktop fixes. It replaces v0.4.1 as GitHub Latest only after exact-source CI,
protected native packaging and independent asset verification pass. Back up an
existing installation before upgrading.

## Highlights since v0.4.1

- Optional Central Hosted Agents can be configured after Server startup in the
  existing Web UI. They use a fixed-origin OpenAI Responses HTTPS API, with
  credentials encrypted in the existing SQLite database. No separate Agent
  service, Bridge client or extra Docker configuration is required. Leaving
  this feature unconfigured does not affect existing Agents. Hosted Agents are
  text-only: they cannot operate the server computer, access a Workspace or
  submit formal Results.
- Web onboarding, member access recovery, work search, explicit Run recovery,
  evidence review and tab-local draft/navigation continuity are improved.
- Completed Bridge outcomes remain authoritative after a network send fails.
  Historical Runtime scope and Room context receipts validate against the
  frozen Delivery, so current Agent configuration cannot invalidate valid
  retained results during reconnect.
- Ordinary Generic CLI, Codex and Pi edits preserve custom Runtime settings.
  Renaming an Agent and creating another with the old name no longer reuses
  the active identity.
- Desktop startup arbitrates instance ownership before Console state locking,
  and pairing activation waits for actual WebView navigation readiness.
  Supported custom, HTTPS and loopback pairing links are consumed consistently.
- Windows packages embed the product icon. Silent missing-WebView2 setup no
  longer blocks on an informational dialog; native workflow failures propagate
  to CI. Desktop output paths and the macOS deployment target are checked.

## Upgrade and compatibility

- Use a recoverable installation when upgrading an existing deployment.
  Back up Central with the repository's online backup procedure, and retain the
  matching old package, database and required operator secrets securely.
- Compared with `v0.4.1`, migrations `0052` through `0055` add Hosted Agent and
  invocation state, the corrective invocation timestamp rule, local-to-trusted
  keyring-root adoption, and member recovery. Applied migration history remains
  immutable. Rollback requires the matching pre-upgrade database and old
  package; do not run old binaries against an upgraded database.
- The released Bridge protocol remains `1.0`. The Hosted feature and historical
  receipt fix are Central-side and do not require a Bridge upgrade by themselves;
  install this release's Bridge to receive the desktop and local Runtime fixes.
- Existing Device/Agent identities and owner data must be preserved on upgrade.
  Canonical `convenewire://` and bounded legacy `agentroom://` handlers remain.
- macOS packages now explicitly require macOS 12.0 or later. Windows Desktop
  requires the Microsoft WebView2 Runtime; the installer does not silently
  install it. Packages remain unsigned, macOS is not notarized, and updates are
  manual. Verify checksums before executing a download.

## Verification and limits

Publication requires successful CI for the exact tagged commit, the complete
protected Release workflow, native Windows stable-to-candidate installer
verification, both Central OCI clean-daemon executions, and verification of all
22 assets before upload, after Draft download and through public download URLs.

The targeted Room context repair has eight new positive/negative WebSocket
regressions; the full Server suite passes 346 tests. Existing deterministic
cross-process acceptance passes six scenarios, with real Codex/Pi invocation
explicitly skipped. Final release-run identities and artifact evidence are
recorded in the repository's `QA-047` acceptance record.

This release does not claim a new two-physical-machine acceptance, exhaustive
Hosted management browser-state acceptance, real-provider production admission,
macOS login-restart/oldest-OS certification, signed distribution or automatic
updates. The corresponding existing acceptance tasks remain open. macOS product
icon customization is separate from the Windows icon repair.
