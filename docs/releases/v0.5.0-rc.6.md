# ConveneWire v0.5.0-rc.6

ConveneWire v0.5.0-rc.6 is a transition prerelease that introduces the
streamlined ADR-0041 distribution and hardens deterministic Discussion
progress. It supersedes v0.5.0-rc.5 for evaluation without changing stable
Latest, which remains v0.4.2.

## Streamlined Distribution

- Standalone Bridge CLI archives are provided only for Linux amd64 and arm64.
- Bridge Desktop is provided for Apple-silicon macOS and 64-bit Windows. Each
  Desktop package includes the same-source, same-version advanced CLI helper.
- Central is provided as one exact-source, checksum-closed source archive with
  Linux amd64, Linux arm64 and macOS arm64 lifecycle helpers. Server and Web
  images are built on the target through Docker Compose.
- The Release is fail-closed around exactly 12 top-level assets: two Linux CLI
  archives, two Desktop archives, one Windows installer, the Central source
  archive and its internal-checksum pin, one outer checksum manifest and four
  license files.

The older OCI bundle builder and historical schema-2 release support remain
available for compatibility and optional offline workflows, but they are not
part of the default rc.6 Release graph.

## Discussion Integrity

- Current Reviewer assessments supersede earlier approval, while any later
  review-relevant projection change invalidates stale approval. Plateau
  finalization cannot bypass a required Reviewer.
- Goal, progress, current task and the complete structured assessment contract
  are preserved under the instruction-size limit. Transcript history consumes
  only its bounded remainder and reports omitted messages explicitly.
- Evidence references contribute to progress only when they resolve to
  persisted Message, Run, Artifact, Result, Memory or Discussion records.
- Lexical near-duplicate detection supplements exact hashes, and recent reply
  text is persisted so restart-between-wave orchestration retains the same
  plateau semantics.

These changes improve orchestration correctness and reduce repeated waves.
They do not add Agent authority, an LLM scheduler or a new public protocol.

## Upgrade And Compatibility

- Protocol remains `1.0`. Existing Team, Device and Agent identities remain
  compatible. Install Central, Web and Bridge from the same candidate.
- Back up Central before upgrading and retain the v0.4.2 package, database and
  required operator secrets. Never start old binaries against a migrated
  database.
- Existing `v0.5.0-rc.5` and older packages retain their historical asset
  layouts; the rc.6 verifier deliberately accepts only the new 12-asset set.
- Packages remain unsigned and unnotarized, Windows Desktop requires WebView2,
  and updates remain manual.

## Verification And Limits

Publication requires exact-source main CI, every protected tagged Release
execution, native Windows v0.4.2-to-rc.6 upgrade and owner-state preservation,
authenticated 12-asset verification, a supported physical Central
source-package installation and cleanup, and immediate independent anonymous
public-download verification. The retained evidence belongs in
`docs/acceptance/qa-063-streamlined-release-workflow.md`.

This candidate does not claim general-production deployment, automatic
updates, signed distribution, Intel macOS support, multiple physical execution
machines, live Remote Provider admission or stable v0.5.0 acceptance.
