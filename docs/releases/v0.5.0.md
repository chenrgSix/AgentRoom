# ConveneWire v0.5.0

ConveneWire v0.5.0 brings the Governed Software-Team Execution Core to the
stable channel for self-hosted use by trusted small Teams. It combines human-
approved Plans, client-owned repository execution and independently verified
results with the deterministic Discussion integrity fixes evaluated in rc.6.

## Governed Execution Core

- Discussion decisions produce versioned Plan proposals; assigned Tech Leads
  can revise them, while humans approve the exact revision and digest.
- Central schedules bounded Runs and retains evidence, approvals and operation
  receipts. Bridge owners retain local repository, Runtime and Git authority.
- Independent verification, explicit evidence adoption and exact-target Git
  integration govern what may become a downstream input. Conflicting target
  changes remain visible rather than being silently merged or overwritten.
- Restart/replay boundaries and separately authorized worktree cleanup preserve
  retained results and client-owned source repositories.

## Discussion Integrity

Current Reviewer assessments replace stale approvals, and review-relevant
progress invalidates an approval that no longer covers the discussion.
Required review cannot be bypassed by plateau finalization. Bounded prompts
preserve the current Task and complete assessment instructions. Evidence counts
toward progress only when references resolve to retained records, while
lexical repetition checks reduce repeated waves across restarts.

## Downloads

The release contains exactly 12 top-level assets:

- Linux amd64 and arm64 standalone Bridge CLI archives;
- Apple-silicon macOS and Windows amd64 Bridge Desktop archives, each including
  the same-source, same-version advanced CLI helper;
- the Windows current-user Desktop installer;
- one Central source archive and its separate internal-checksum pin, with
  Linux amd64/arm64 and macOS arm64 lifecycle helpers;
- the outer `SHA256SUMS` and four license/policy files.

Central Server/Web images are built on the target through Docker Compose.
Docker is required for the source-package deployment. Intel macOS Desktop is
not included. Historical packages and RC assets remain immutable.

## Upgrade From v0.4.2

Back up Central online and verify the backup before upgrading. Retain the
matching v0.4.2 binaries and required operator secrets for rollback. Upgrade
Central/Web and Bridge together; protocol remains `1.0` and the Central schema
advances through migration `0086` with installation, Team, Device and Agent
identity preservation. Rollback means restoring the verified pre-upgrade
backup into an isolated target with matching old binaries, never opening the
migrated database with an old Server.

## Verification And Scope

The release admission record is
[`QA-060`](../acceptance/qa-060-v0.5.0.md). It retains checksum-pinned Central
upgrade/rollback, Owner-accepted packaged dual-Bridge product execution,
independent verification, exact integration and cleanup, together with
exact-source CI and protected native packaging/download evidence.

Packages remain unsigned and unnotarized, Windows Desktop requires WebView2,
and updates remain manual. This stable channel is not a claim of general-
production or public multi-tenant admission, signed distribution, automatic
updates, macOS login-restart acceptance, live-model quality, multiple physical
execution machines or live Remote Provider acceptance. Optional Remote
Evidence remains disabled without operator credentials and is not a Core
prerequisite.
