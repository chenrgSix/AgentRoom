# AgentRoom v0.2.0-rc.4

This release candidate makes daily Team and Room administration recoverable,
keeps message composition out of the timeline, and validates local Runtime
configuration before it changes a running Bridge.

## Highlights

- Docks the Room composer in normal layout so it no longer covers conversation
  history, and separates message, Team, participant, and lifecycle busy states.
- Adds client Message IDs, pending and failed rows, and same-ID retry so an
  ambiguous send can recover without creating a duplicate Message or Run.
- Reconciles the selected Room from an authorized Team-change cursor, with a
  bounded fallback for hidden tabs, reconnects, service restarts, or stream
  failure instead of broad two-second refreshes.
- Makes Team creation prominent and lets Owners assign human and Agent
  participants independently for each Room.
- Adds Owner-only rename, archive, and restore for Teams and Rooms plus
  disable/enable for Agents. History and stable IDs remain intact, and active
  work fences lifecycle changes.
- Lets Bridge owners add multiple local Agents and edit one selected Agent in a
  modal without rebuilding the sibling roster or changing stable identity.
- Adds explicit detected-executable actions and bounded Codex/Pi draft
  preflight. Preflight never saves configuration or restarts the Bridge, and
  cannot overlap active Team work, enrollment, another probe, or Agent save.

## Upgrade and Compatibility Notes

- Upgrade the central service and Bridge from the same tag. The central SQLite
  database applies migrations 0017 and 0018 for recoverable resource lifecycle
  and idempotent member Message submission.
- Archive and disable are reversible controls, not deletion. Archived Teams and
  Rooms disappear from normal navigation but remain available to Owners in the
  recovery surface.
- Existing Bridge configuration and stable Agent identities remain compatible.
  Detected executable paths are never applied automatically.
- macOS desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

Local release preflight passed 7 schemas and 30 fixtures, 95 Server tests, 12
Web tests, 4 contract tests, deterministic cross-process E2E, maintained
Markdown lint, Compose and release-script validation, ordinary Bridge tests and
vet, and Desktop-tagged tests, vet, and native compilation. Credentialed local
Codex and Pi execution remains an explicit live test and is not part of
ordinary CI.

## Remaining Gates

- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- This candidate targets trusted small teams, not an internet-scale identity or
  high-availability service.
