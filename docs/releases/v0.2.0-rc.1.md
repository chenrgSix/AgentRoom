# AgentRoom v0.2.0-rc.1

This preview establishes the first installable trusted-team baseline. It keeps
the central Web Room lightweight while allowing existing Codex and Pi runtimes
to join through the optional Go Bridge or pull work through MCP.

## Highlights

- Adds Chinese-first trusted-team setup, Owner recovery, secure Web sessions,
  one-time member invitations, and member management.
- Separates Bridge process and connection state, defaults public HTTPS to
  renewable system-CA trust, and retains legacy SHA-256 pin compatibility.
- Adds opt-in macOS login startup, redacted diagnostics, and manual-only update
  checks that never download or execute unsigned code.
- Adds a non-root, read-only Server plus Caddy Compose profile with verified
  online backup and no-overwrite streamed restore workflows.
- Adds push, pull-request, and immutable draft Release quality gates.

## Upgrade and Security Notes

- Migration `0014_trusted_web_identity.sql` is additive and runs at Server
  startup. Create a verified backup before changing deployment mode.
- `local` Web auth remains loopback-only. `trusted-team` Web APIs accept only
  the secure host Cookie; legacy Web Bearer sessions are rejected. Device and
  MCP Bearer credentials are unchanged.
- Trusted setup safely adopts one unambiguous existing Owner or lone bootstrap
  User. Ambiguous legacy identity/member states fail closed.
- New public HTTPS Bridge enrollment uses `system_ca`. Existing configurations
  containing only a certificate fingerprint remain pinned.
- macOS desktop archives are intentionally unsigned and unnotarized. Verify the
  published checksum, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow must publish exactly five portable CLI archives and two
native macOS desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive paths, launchers, executable modes, architectures, versions, GUI bundle
metadata, and license files before and after upload.

## Verification

The release source passed schema validation (7 schemas and 29 fixtures), all 57
Server tests, 4 Web tests, contract tests in TypeScript and Go, deterministic
cross-process MCP and managed Bridge E2E, documentation lint, ordinary and
Desktop-tagged Bridge tests/vet, Docker build, Caddy proxy checks, graceful
shutdown, and backup/restore acceptance including a 67 MB streamed fixture.
The credential-using Codex/Pi live test remains explicit and was not invoked by
the ordinary suite.

## Known Acceptance Gates

- `BRG-013` remains active until a real macOS login restart proves one desktop
  instance and no credential in the LaunchAgent.
- `QA-002` remains ready until two physical machines produce reviewed online
  and offline/reconnect Codex evidence.
- This candidate is for trusted small teams, not an internet-scale identity or
  high-availability service.
