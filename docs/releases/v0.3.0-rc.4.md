# AgentRoom v0.3.0-rc.4

This release candidate adopts the AgentRoom Community License 1.0 and fixes
Windows Runtime discovery and preflight for native executables and npm command
shims such as `codex.cmd`.

## Highlights

- Replaces the former noncommercial-only terms with the AgentRoom Community
  License 1.0. It permits commercial and noncommercial use inside one
  organization, source modification, self-hosting, product integrations, and
  one dedicated deployment for one customer.
- Retains separate commercial licensing for shared multi-customer hosting,
  competing standalone resale, and external white-label distribution without
  the required attribution.
- Adds the versioned trademark policy and contributor agreement, aligns npm,
  Docker, application, installer, and documentation metadata, and ships
  `TRADEMARKS.md` with every Bridge package and as a top-level Release asset.
- Accepts regular Windows `.exe`, `.com`, `.bat`, and `.cmd` Runtime launchers
  without requiring Unix execute bits. Unix-like systems retain their existing
  execute-bit boundary.
- Applies the shared platform rule to Runtime discovery, readiness projection,
  draft preflight, configuration save, and CLI enrollment.
- Adds native Windows CI coverage that passes an npm-style `codex.cmd` through
  PATH discovery and the authenticated Runtime preflight endpoint.

## Upgrade and Compatibility Notes

- Upgrade the central Server, Web UI, contracts, and Bridge from the same tag.
  This candidate has no new central database migration.
- This version is distributed under the AgentRoom Community License 1.0. The
  license shipped with each released version controls that version; review
  `LICENSE`, `COMMERCIAL-LICENSE.md`, and `TRADEMARKS.md` before deployment.
- Existing configured Windows Codex paths such as npm's `codex.cmd` do not need
  to be changed. Detection and preflight now accept them directly.
- The Windows Desktop package still targets Windows 10 or newer on amd64/x64,
  requires the system WebView2 Runtime, and remains unsigned.
- Automatic updates and Windows login startup remain unsupported.
- Back up the central SQLite database and local Bridge configuration before
  upgrading. Version-aligned rollback may require restoring the matching
  database backup after migration.

## Artifacts

The Release workflow publishes five portable CLI archives, two native macOS
Desktop ZIPs, one Windows Desktop portable ZIP, one Windows per-user installer,
`SHA256SUMS`, `LICENSE`, `NOTICE`, `COMMERCIAL-LICENSE.md`, and `TRADEMARKS.md`.
The committed verifier requires exactly 14 assets and checks their names,
checksums, archive paths, architectures, embedded versions, GUI and installer
metadata, launchers, and license files before and after upload.

## Verification

Candidate admission requires exact-source contract validation and generation,
production builds, Server, Web, contract, Go, native macOS and Windows Desktop,
deterministic cross-process E2E, documentation, Compose, release-script,
packaging, installer lifecycle, and clean-download checks. The native Windows
job must also execute the `codex.cmd` discovery and preflight regression.
Credentialed Codex and Pi execution remains an explicit live test and is not
part of ordinary CI.

## Remaining Gates

- Human testing on a physical Windows machine remains separate from native CI,
  including SmartScreen, wizard layout, tray interaction, missing-WebView2
  presentation, and a live Codex command-shim launch.
- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- Packages remain unsigned, unnotarized, and manual-update-only.
- `v0.2.0` remains the stable Latest release while this candidate is evaluated.
