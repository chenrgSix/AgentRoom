# ConveneWire v0.5.0-rc.5

ConveneWire v0.5.0-rc.5 is a transition prerelease that makes local deployment
and daily use calmer without expanding the completed Governed Software-Team
Execution Core. It supersedes rc.4 for evaluation; stable Latest remains
v0.4.2.

## What Changed Since v0.5.0-rc.4

- A Central operator can explicitly choose ordinary trusted-LAN browser HTTP,
  so another computer on the LAN can open the Web UI without installing a
  private CA. Bridge, Device and machine-authority traffic remains pinned to
  HTTPS.
- Existing installations can move deliberately between `lan_http` and
  `direct_https` with the controller's commit-last, rollback-safe migration.
- The Central Web UI now uses neutral graphite and white surfaces with indigo
  interaction authority. Green is reserved for semantic success instead of
  tinting navigation or general work surfaces.
- Bridge Desktop keeps Team and Room entry focused on everyday collaboration.
  The private-CA browser assistant now lives under a collapsed **Advanced
  browser trust** item in Settings and clearly says normal LAN HTTP requires no
  CA.

## Deployment Choices

- **Trusted LAN:** choose `lan_http` for the browser. No browser CA installation
  is required; keep the Central host scoped to a network you trust.
- **Private HTTPS:** choose `direct_https` and explicitly establish browser
  trust on each relevant user/machine when using a private CA.
- **Public HTTPS:** use a publicly trusted certificate and normal system trust.

These choices affect browser entry only. Repository paths, Git credentials,
Runtime commands, Device credentials and owner-machine operations remain local
to Client/Bridge and are never granted to the browser HTTP channel.

## Inherited Candidate Scope

The complete plan-owned, proof-carrying execution route from Discussion and
human approval through deterministic scheduling, bounded local execution,
verification, exact-target integration, evidence adoption, retry,
supersession, delegation and quorum remains included. Remote commit/CI evidence
remains optional and inactive without an operator-supplied runtime credential.

## Upgrade And Compatibility

- Back up Central before upgrading and retain the v0.4.2 package, database and
  required operator secrets. Never open an upgraded database with old binaries.
- Protocol remains `1.0`; existing Device/Agent identities and migration history
  through `0086` remain compatible. Install Central, Web and Bridge from the
  same candidate.
- Existing direct-HTTPS installations do not switch transport automatically.
  Use the explicit controller migration only when the Owner intends to change
  browser transport.
- Packages remain unsigned; macOS packages are not notarized, Windows Desktop
  requires WebView2 and updates remain manual.

## Verification And Limits

Publication requires exact-source CI, every protected Release job, native
Windows stable-to-candidate upgrade, both Central OCI clean-daemon executions,
closed-set verification before/after upload and a separate anonymous public
download verification. See
`docs/acceptance/qa-062-v0.5.0-rc.5.md` for retained evidence.

This candidate does not claim production deployment, automatic update,
signed/notarized distribution, multiple physical execution machines, live
Remote Provider admission or automatic trust-store mutation.
