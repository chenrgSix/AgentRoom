# AgentRoom v0.2.0-rc.2

This release candidate makes multi-Agent Room conversations genuinely parallel
and strengthens the Bridge recovery and diagnostic boundaries introduced in
`v0.2.0-rc.1`.

## Highlights

- Unifies normal Room messages, one-Agent mentions, and multi-Agent discussions
  behind the same composer instead of exposing a separate discussion mode.
- Dispatches every eligible participant in one durable Wave concurrently,
  closes the barrier only after terminal outcomes, and advances in stable
  participant order regardless of callback arrival order.
- Adds deterministic progress, budget, plateau, pause, extension, cancel, and
  finalization decisions while keeping the Orchestrator model-independent.
- Persists Wave plans and results so Coordinator restarts cannot duplicate
  participant Runs, anchors, budget charges, or finalization.
- Prevents incompatible Bridge inbox records from causing reconnect loops and
  preserves safe Codex/Generic failure category, exit code, and stderr-presence
  metadata without transporting raw stderr.
- Completes the self-contained central Compose deployment and operations guide.

## Upgrade and Compatibility Notes

- Back up the central SQLite database before upgrading. Migration
  `0015_discussion_waves.sql` is additive and creates the durable Wave and Turn
  state required by the new Orchestrator.
- Upgrade the central service and Bridge from the same tag. `v0.2.0-rc.1`
  predates strict incompatible-inbox fencing and cannot repair those records.
- Existing Discussion rows are recovered through the deterministic scheduler;
  expired work is terminated rather than dispatched after restart.
- macOS desktop archives remain intentionally unsigned and unnotarized. Verify
  `SHA256SUMS`, then trust only the extracted AgentRoom app. Never disable
  Gatekeeper globally.

## Artifacts

The Release workflow publishes five portable CLI archives and two native macOS
desktop ZIPs, plus `SHA256SUMS`, `LICENSE`, `NOTICE`, and
`COMMERCIAL-LICENSE.md`. The committed verifier checks names, checksums,
archive layout, launchers, executable modes, architectures, embedded versions,
GUI bundle metadata, and license files before and after upload.

## Verification

The tagged source passed main CI with 7 schemas and 30 fixtures, 89 Server
tests, 8 Web tests, 4 contract tests, deterministic cross-process E2E,
maintained Markdown lint, ordinary and Desktop-tagged Bridge tests/vet, central
Compose validation, and native desktop compilation. Development validation also
completed an isolated parallel Codex and Pi Wave; credentialed live Runtime
execution remains explicit and is not part of ordinary CI.

## Remaining Gates

- `BRG-013` still requires a real macOS logout/login or restart proving exactly
  one desktop instance and no credential stored in the LaunchAgent.
- `QA-002` still requires reviewed online and offline/reconnect evidence from
  two physical machines.
- This candidate targets trusted small teams, not an internet-scale identity or
  high-availability service.
