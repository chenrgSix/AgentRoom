# QA-062 ConveneWire v0.5.0-rc.5 Transition Release

Date: 2026-09-04

Status: accepted and published. The release goal was frozen before tag creation
or publication. Delivery state lives only in `docs/TASKS.md`.

## Goal

Publish one immutable `v0.5.0-rc.5` prerelease containing the accepted
post-rc.4 product corrections:

- explicit same-host LAN browser HTTP while Bridge and machine-authority
  traffic remain pinned to HTTPS;
- the neutral Graphite Central visual system; and
- the advanced private-HTTPS browser-trust assistant under Bridge settings
  instead of the everyday collaboration overview.

The candidate supersedes rc.4 for evaluation without moving or deleting any
older tag, Release or asset. Stable GitHub Latest remains `v0.4.2`.

## Product And Authority Boundary

- Ordinary trusted-LAN browser use may select explicit `lan_http` and requires
  no CA installation. Direct private HTTPS remains an explicit alternative;
  public HTTPS continues to rely on normal system trust.
- Bridge, Device, Runtime, repository and owner-machine authority never use the
  LAN HTTP browser channel. Their exact-origin HTTPS boundary is unchanged.
- Central governs Plans, scheduling, authorization, Evidence/Proof/Adoption and
  operation receipts. Repository paths, Git credentials and commands remain
  Client/Bridge and machine-Owner authority.
- The visual and Bridge navigation changes add no execution, credential,
  repository, trust-store or automatic-update authority.
- Remote Evidence stays an optional, credential-free-by-default extension.

## Admission Gates

1. Candidate source is clean, equals `origin/main` and passes exact-source CI,
   including repository, Go, native macOS Desktop and native Windows Desktop.
2. A new annotated `v0.5.0-rc.5` tag peels to that exact commit and a new empty
   prerelease Draft exists before the Release workflow starts.
3. Every protected Release job succeeds, including native Windows
   `v0.4.2`-to-rc.5 in-place upgrade with retained Owner state, both Central OCI
   clean-daemon executions and the closed 22-asset checks before upload and
   after authenticated Draft download.
4. The Draft is published as a prerelease without changing stable Latest.
5. A separate credential-free client downloads and verifies the complete
   public asset set, exact checksums and embedded Central archive identities.
6. Only after publication, README and product-site copy identify rc.5 as the
   current prerelease; the exact Pages source/build bytes are independently
   compared under `SITE-005`.
7. Every task-owned download, build, cache and temporary root is physically
   removed, with no new historical four-prefix entries in either inspected
   macOS temporary location.

A failed, canceled, timed-out, ambiguous or unverifiable gate authorizes no tag
movement, asset replacement, skipped assertion or completion claim. A bad
candidate receives a new version identity.

## Required Completion Evidence

The accepted record must retain the source SHA, annotated-tag object, CI and
Release run IDs, all protected conclusions, Windows upgrade evidence, both OCI
architectures, the closed asset count/bytes/checksum, authenticated and public
verifier results, publication metadata, stable-Latest preservation, SITE-005
deployment equality and physical cleanup snapshots.

## Explicit Limits

This prerelease does not claim signed/notarized packages, automatic updates,
production deployment, physical trust-store mutation on every supported
platform, exhaustive Hosted Agent production-browser states, multiple physical
execution machines or a live Remote Provider. Stable admission remains
`QA-060` and requires its separately frozen backup, upgrade, smoke and rollback
gates.

## Closed Asset Verification And Publication

The protected workflow verified the closed 22-asset set before upload and
again after a fresh authenticated Draft download. The Draft was published at
`2026-09-04T09:11:28Z` as the public
[v0.5.0-rc.5 prerelease](https://github.com/chenrgSix/ConveneWire/releases/tag/v0.5.0-rc.5).
It is non-draft and prerelease; stable `v0.4.2` remains GitHub Latest.

The separate public check removed GitHub credential variables, ignored user
curl configuration and downloaded all assets through public Release URLs. Its
first diagnostic attempt proved every manifest checksum, then the tagged
verifier failed when the sandbox rejected the default user Go cache. Its owned
root disappeared and snapshots were unchanged. The second attempt moved all
caches into its owned root and downloaded the complete set, but the verifier
correctly rejected the now-advanced public-copy checkout because it was not the
tagged release source. That root also disappeared with unchanged snapshots.
Neither diagnostic attempt changed a tag, asset or test.

The accepted attempt used a detached isolated checkout of the exact tag source,
one run-scoped `TMPDIR`, `GOCACHE`, `GOMODCACHE` with `-modcacherw`, and npm
cache. The full tagged verifier exited zero and reported:

- exact source `f19cde69207db2ac2449271842c255fa6fd451cc`;
- asset count `22` and total bytes `562155758`;
- outer `SHA256SUMS` digest
  `03b04890b044e219cc3b75d36211e90da85f9c151a40e95352e8d495b1ccf3a2`;
- all five CLI archives, three Desktop archives, the Windows installer and
  four checksum-pinned Central archives matched their version, source,
  architecture and retained license boundaries; and
- the isolated checkout, downloaded assets, caches and verifier roots were
  physically removed.

The accepted public run's before/after four-prefix snapshot digest was
`bed355887a38ea05bae4e42adf5ffc3a727a419065e1ed31cec0f517f66f47d0`.
