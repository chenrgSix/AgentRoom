# QA-061 ConveneWire v0.5.0-rc.4 Transition Candidate

Date: 2026-09-04

Status: accepted and published. The release goal was frozen before tag creation
or publication. Delivery state lives only in `docs/TASKS.md`.

## Goal

Publish one immutable `v0.5.0-rc.4` prerelease that carries the accepted
BRG-072 private-browser trust assistant and BRG-073 platform-neutral correction
into installable Bridge/Desktop packages. The candidate supersedes
`v0.5.0-rc.3` for evaluation without
moving, replacing or deleting the rc.3 tag or assets. Stable Latest remains
`v0.4.2`.

The release is a transition candidate for the already completed Governed
Software-Team Execution Core. It does not add another Core capability or
change the client-owned repository boundary.

## Candidate Delta

Compared with `v0.5.0-rc.3`, the candidate adds only the accepted BRG-072 and
BRG-073 behavior and its documentation:

- an already paired private-scoped Bridge/Desktop can derive a self-contained
  Windows PowerShell trust command from its exact authenticated public CA;
- the command verifies the embedded and temporary certificate bytes with the
  displayed full SHA-256 digest before installing into the invoking Windows
  user's Root store;
- the command owns and removes only its randomized temporary certificate file,
  and a separate exact-certificate removal command is displayed;
- opening or copying the assistant performs no network request, creates no
  client-entry ticket and exposes no credential, private key, repository or
  local Runtime authority; and
- public-CA installations and invalid, stale or unavailable private trust
  expose no assistant.
- the entry explains that any other computer may need private-CA trust and
  offers separate exact Windows and macOS current-user commands; Linux remains
  supported with an honest distribution/browser-specific guidance boundary.

Installing persistent browser trust remains an explicit target-user action.
The candidate does not silently mutate an operating-system trust store and
does not claim physical target-machine execution from generated-command tests.

## Authority And Compatibility Boundary

- Central still governs Plans, scheduling, bounded authorization,
  Evidence/Proof/Adoption and operation receipts.
- Repository paths, Git remotes, Git/SSH credentials, fetch/pull/push,
  worktrees and Git command execution remain Client/Bridge and machine-Owner
  authority.
- Browser trust does not grant Team entry. One-use client-entry tickets remain
  independently created only by an explicit Owner action.
- A root certificate already installed for the same Windows user remains
  available across ordinary ConveneWire, browser and operating-system updates.
  A different machine/user or a rotated Central CA requires a new explicit
  trust action.
- Existing Device/Agent identities, Bridge protocol `1.0`, Central migration
  history through `0086`, canonical `convenewire://` handlers and bounded
  legacy `agentroom://` handlers remain compatible.
- The Remote Evidence implementation remains an optional,
  credential-free-by-default extension and is not a Core or release
  dependency.

## Admission Gates

Publication requires all of the following:

1. the exact candidate commit is clean, equals `origin/main`, and passes all
   Repository, Go, native macOS Desktop and native Windows Desktop main-CI
   jobs;
2. a new annotated `v0.5.0-rc.4` tag resolves to that exact commit and a new
   empty prerelease Draft exists for the same immutable tag;
3. all 19 protected Release workflow jobs check out the resolved full SHA and
   pass, including native Windows `v0.4.2`-to-candidate in-place upgrade with
   Owner-state preservation;
4. both Central OCI architecture bundles execute in clean Docker daemons and
   all four Central archives consume their matching once-built bundle;
5. the exact closed set of 22 assets passes the tagged verifier before upload,
   after authenticated Draft download and after a separate credential-free
   public download;
6. the Draft is published as a prerelease while stable Latest remains
   `v0.4.2`;
7. post-publication README and product-site copy identify rc.4 as the current
   prerelease, pass their static/build/docs gates and match deployed Pages
   bytes; and
8. every task-owned download, cache and temporary root is physically removed,
   with no new `agentroom-*`, `agent-room-*`, `convenewire-*` or
   `convene-wire-*` directory in either inspected temporary location.

A failed, canceled, timed-out, ambiguous or unverifiable gate authorizes no
tag movement, asset replacement, publication, skipped assertion or completion
claim. A bad candidate receives a new version identity.
