repairs. This is a new prerelease, not a promotion of a historical Draft or a

## Admission boundary

The release includes the optional Hosted Agent, product experience and Bridge
audit work since `v0.4.1`, including `RUN-017` at `4b81737`. The most recent
targeted repair passed two full 346-test Server runs, contract/schema/build
checks and six deterministic E2E scenarios. Those local results do not replace
exact-source CI or native release-package evidence.

Publication requires:

1. an exact commit that passes Repository, Go, native macOS and native Windows
   main CI;
2. an annotated `v0.5.0-rc.1` tag naming that commit and an empty prerelease Draft;
3. the protected Release workflow checking out that one SHA for all jobs;
4. native Windows `v0.4.1`-to-`v0.5.0-rc.1` install/upgrade/uninstall verification,
   preserved owner state and installed/staging/ZIP executable identity;
5. both immutable Central OCI architectures passing clean-daemon execution and
   all four matching Central archives with independent internal-checksum pins;
6. the exact 22 assets passing the tagged verifier before upload, after Draft
   download, and in a separate clean authenticated local download;
7. publication as a prerelease, followed by a fresh anonymous download and the
   same tagged verifier; and
8. public stable Latest remaining `v0.4.1`.

Failed or ambiguous gates do not authorize publication, tag movement, asset
replacement, skipped assertions or relabeling the preview as stable.

## Explicit exclusions

The open `WEB-050`, `QA-038` and `BRG-013` criteria are not marked complete by
this prerelease. In particular, this does not substitute for exhaustive Hosted
browser-state acceptance, live-provider production approval, physical desktop
activation or macOS login-restart acceptance. Existing historical physical
records are not reused as evidence for newly versioned preview binaries.

No production deployment, user database, existing application, platform trust
store or model credential is changed during this release procedure. Only
repository commits, the newly named tag/Draft and its protected build workflow
are in scope. Existing published and historical Draft assets are preserved.
