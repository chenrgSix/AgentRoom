# QA-037: ConveneWire v0.4.1

## Admission decision

The Owner authorized pushing `main` and publishing `v0.4.1` as the stable
Latest release. The exact `v0.4.1-qa035.1` candidate at
`152892e59e90fe17799274009141b07714262378` is the product source admitted by
the reviewed two-physical-machine schema-v4 acceptance. Changes after that
candidate and before this record contain only acceptance and release
documentation; no Server, Web, contract, controller, Bridge, Desktop,
installer, workflow, or packaging implementation changed.

The candidate GitHub Release remains an unpublished prerelease Draft. It is
not renamed, published, or reused as the stable Release. `v0.4.1` receives its
own annotated tag, exact-source CI, empty non-prerelease Draft and independently
built assets.

## Candidate evidence

The reviewed
[schema-v4 physical record](evidence/qa-002-20260830-schema-v4.md) binds the
exact candidate source to:

- a packaged macOS arm64 Central reporting Release `v0.4.1-qa035.1` and source
  commit `152892e59e90fe17799274009141b07714262378` from live metrics;
- a packaged Windows amd64 Bridge reporting the same source commit through its
  authenticated hello;
- the selected Windows installer, desktop ZIP and running executable digests;
- canonical configured-client `convenewire://` pairing with scoped private
  trust and no OS CA import, TLS bypass, token/credential copy, manual `.env`,
  or OpenSSL step;
- a passing Codex Runtime self-test with no unexpected console window; and
- exact same-Device offline/reconnect and online Runs, fresh heartbeat,
  captured metrics and an explicit human `PASS` receipt within one bounded UTC
  window.

`QA-036` separately records uncached native Windows execution of the Job Object
parent/child/grandchild and console-suppression regressions. Hosted Windows,
physical Windows and target-host Central evidence remain distinct claims.

## Stable publication gates

Before publication, all of the following must pass for the exact annotated
`v0.4.1` tag:

1. the tag peels to one full commit already accepted by main CI;
2. an empty non-prerelease Draft exists before workflow dispatch;
3. the protected Release workflow reruns every repository and Go gate, native
   macOS/Windows Desktop jobs and both clean-daemon Central OCI executions;
4. Windows installs current stable `v0.4.0`, upgrades in place to `v0.4.1`,
   verifies protocol registration, installed/staging/ZIP executable equality
   and owner-state preservation, then uninstalls without deleting owner state;
5. exactly 22 assets pass the committed verifier before upload and after Draft
   download;
6. a separate clean pre-publication download passes the same verifier;
7. the Draft is published as a non-prerelease and becomes GitHub Latest; and
8. a fresh anonymous public download of all 22 assets passes the tagged
   verifier and the public Latest endpoint resolves to `v0.4.1`.

The release remains unsigned, unnotarized, manual-update-only, and intended for
trusted small Teams. Stable publication does not claim public Internet multi-
tenant hardening, signed platform distribution, automatic updater delivery, or
general availability beyond that scope.
