## Stable Product Boundary

The stable claim is limited to source-available, self-hosted use by trusted
small Teams:

- humans govern exact Plans, approvals, evidence adoption and repository
  integration operations;
- Central governs Plan, scheduling, bounded authorization,
  Evidence/Proof/Adoption and operation-receipt facts;
- repository paths, Git remotes, Git/SSH credentials, fetch/pull/push,
  worktrees and Git command execution remain Client/Bridge and machine-Owner
  authority;
- the Remote Evidence implementation remains an optional,
  credential-free-by-default extension and is not a Core or stable-admission
  dependency; and
- packages remain unsigned and unnotarized, updates remain manual, and the
  release is not a public multi-tenant or general-production admission.

`BRG-013`, `WEB-050` and `QA-038` remain separate active work. Stable
publication does not close them and does not claim macOS login-restart,
exhaustive Hosted-Agent production-browser states, a paid/live provider,
multiple physical execution machines, signed distribution, automatic updates
or a production deployment. A future claim in any of those areas requires its
own accepted task and current evidence.

## Failure Policy

Any failed, canceled, timed-out, ambiguous or unverifiable gate authorizes no
tag movement, asset replacement, Draft publication, skipped assertion, Latest
change or completion claim. Diagnose the failure, record it, commit a bounded
repair with regression evidence, select a new exact source and rerun every gate
whose source or output may have changed.

Published and historical Release records are append-only evidence. A bad
candidate gets a new version identity; it is never repaired in place.
