1. 安装中央服务

如果你已经有可访问的中央服务，可以直接跳到创建 Team 与 Room。

当前 rc.6 使用一个与宿主架构无关的 Central 源码包，通过归档内的 convenewirectl 构建、安装和管理中央服务；稳定 v0.4.2 仍保留自己的历史分平台包，应遵循对应 Release 说明。

  1. 准备 Linux amd64/arm64 或 Apple-silicon macOS 主机，以及 Docker Engine 24+ 和 Compose 2.20+。
  2. 下载唯一的 convenewire-central_*_source.tar.gz、它的 *.SHA256SUMS.sha256 pin 和外层 SHA256SUMS；先核验下载，再按指南校验归档内部清单。
  3. 使用归档自带的安装命令初始化 Owner，并选择浏览器入口：可信局域网可用 lan_http，无需安装 CA；公网使用公共 HTTPS；只有高级私有 HTTPS 需要为浏览器建立私有 CA 信任。

源码包在目标主机通过 Docker Compose 构建 Server 与 Web；宿主机不需要安装 Node.js、Go、Git 或 OpenSSL。浏览器选择不会降低 Bridge、Device 或执行通道的 HTTPS 边界。公开访问仍需要合适的网络、DNS 和 TLS 配置；不要把局域网或仅限本机的模式暴露到互联网。

打开完整中央安装指南 ↗

Windows 可作为 Bridge 客户端；当前没有 Windows 原生中央服务发布包。传统手工部署见Compose 指南。

最新源码：本地体验

需要开发调试或体验后续源码改动时，可在安装了 Node.js 22 与 npm 的开发环境中运行源码。以下是本地开发方式，不是公网生产部署。

准备项目
git clone https://github.com/chenrgSix/ConveneWire.git
cd ConveneWire
npm ci
npm run db:migrate
终端 1 · API
npm run dev:server
终端 2 · Web
npm run dev:web

浏览器打开 http://127.0.0.1:5173。API 默认在本机 3000 端口。本地入口会创建开发会话；可信 Team 的部署使用独立的 Owner 设置与安全会话流程。

只体验中央或演示 Agent 不需要开发 Bridge。涉及 Bridge 开发时，再按仓库说明准备 Go 工具链。

2. 创建 Team 与 Room

Team 是协作空间，Room 是一组人和 Agent 共同讨论、推进工作的地方。

  1. 进入你的中央服务，完成相应模式的首次访问或 Owner 初始化。
  2. 创建一个 Team，例如“产品研发”。
  3. 创建第一个 Room，例如“产品迭代”，然后选择接入方式。

可以先使用演示 Agent 熟悉操作，不用填写 API Key。演示只模拟回复，不会替你真正编写代码或完成业务任务。

3A. 创建中央 Agent

最新源码 · Owner 配置

选择创建中央 Agent，在页面里填写名称、角色、模型名称与 API Key，并明确勾选允许加入的 Room，然后点击验证并创建。

  • 不需要额外部署 Agent 服务，不需要在中央安装 pi 或 Codex。
  • 配置保存在现有数据库，API Key 加密存储；不需要 Hosted 专属秘密文件目录。
  • 默认不授权任何房间。创建后，通过“进入房间对话”前往已授权的 Room。
  • 验证会调用提供方，可能产生用量。请求结束后，输入框中的 API Key 会清空；后续可替换、撤销或停用。

当前边界 仅支持固定的 OpenAI Responses API，不能填写任意兼容接口地址。中央 Agent 不能操作电脑、访问文件、执行命令或工具，也不能提交正式 Result、审核结果或自行完成任务。

远程模型会收到本次 Run 获准使用的上下文。请确认房间内容适合发送给提供方，并按提供方政策管理权限和费用。

3B. 连接本机 Agent

需要使用本机代码、文件或工具时，在执行工作的电脑上安装 Bridge，并准备好相应的 Codex 或 pi Runtime。

  1. 在 Owner 网页中选择连接本机 Agent，创建 Device 配对。
  2. 打开或粘贴配对链接至 Bridge，核对中央地址和两端显示的确认短语，再由 Owner 返回网页批准。
  3. 在本机完成 Runtime、工作区与权限配置，再将 Agent 加入合适的 Room。

配对建立的是有边界的设备信任，不会绕过 Runtime 的沙箱或审批。远程模型凭据与本机工作区配置仍由 Runtime 所在电脑管理。

ConveneWire 不接管你的 Git 仓库或 Git 凭据。仓库路径、Git/SSH 凭据、worktree 和 Git 命令由本地 Client/Bridge 控制，Central 只保留计划、授权、证据和操作回执。

打开 Bridge 使用指南 ↗

Bridge 桌面包目前未签名，macOS 包未公证；Windows 桌面版需要 WebView2。请按官方发布说明核验下载来源。Windows、macOS 和 Linux 都可作为客户端。可信局域网的浏览器 HTTP 入口无需安装 CA；只有选择私有 HTTPS 时，才需要在目标浏览器建立信任。当前 RC 把带指纹校验的 Windows/macOS 当前用户命令放在 Bridge“设置”的高级浏览器信任区域，Linux 则显示发行版/浏览器相关说明；它不会自动修改系统信任。

4. 收到第一条回复

  1. 进入 Agent 已获授权的 Room，确认它在当前房间中可用。
  2. 在输入框输入 @，从建议列表选择 Agent，再写下问题。
  3. 发送后查看 Run 状态与回复。普通文本中写一个名字，不等于创建了结构化提及。

注册成功只是接入完成，收到实际回复才说明这条协作路径已经走通。中央 Agent 不需要 Bridge 在线，本机 Agent 则需要相应的设备与 Runtime 可用。

5. 继续与恢复工作

让任务有清晰的验收标准

创建任务时可以展开“交付要求”，每行填写一条可核验标准。参考模板只会追加，不会覆盖已有内容。运行和交付会关联到任务，支持的 Agent 可以提交正式 Result，由有权限的人审核。

先看证据，再决定是否完成

从 Result 直接打开成果预览。内容摘要通过校验并不代表内容可信；文档只以纯文本显示，不执行其中脚本。审核接受与完成任务仍是有权限的人工操作。

结果未知时，不盲目重跑

检查原运行事件与真实外部结果，记录明确的确认理由，再单独决定是否发起新尝试。同一标签页会保留未确认操作的核对记录；不要通过关闭标签页、清空浏览器数据来重复执行。

失去会话，也不要重新邀请自己

已有普通成员请让 Owner 在“Team 成员”生成 15 分钟的一次性恢复码，再在登录页选择“成员重新登录”。恢复保留原身份与工作归属，并退出旧网页会话。此入口仅支持只属于当前 Team 的普通成员，不支持 Owner 或多 Team 身份。

找回更早的工作

工作台可按负责人和状态筛选，并继续加载更多任务；Room 顶部可以加载更早的消息，保持当前阅读位置。
