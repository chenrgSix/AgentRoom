CONVENEWIRE BRIDGE GUIDE

ConveneWire Bridge 使用说明

Bridge 是做什么的

Bridge 把这台设备上的 Codex 和 Pi 安全连接到中央 Team。中央服务负责分配任务，本机继续掌握 Runtime、工作区、文件权限和执行审批。

日常怎么用

  1. 在“概览”确认 Bridge 正在运行，并查看中央服务是否已连接。
  2. 在“本机 Agent”检查 Runtime、工作区和文件策略；测试或修改配置需要在本机明确操作。
  3. 在中央 ConveneWire 中提及对应 Agent 即可分配任务；Bridge 会在本机执行并返回结果。
  4. 连接、隐私、配对恢复、更新和诊断入口都集中在“设置”。

Codex 会话说明

ConveneWire Bridge 与 Codex Desktop/CLI 各自运行本地 App Server；当前 ConveneWire 版本没有启用共享 daemon。App Server 能接受多个连接，不代表 Desktop 已配置为连接 Bridge 的进程。

先分清三个概念

Task
ConveneWire 中持续协作的上下文。切换 Task 会隔离会话。
Run
每次提及智能体触发的一次执行。同一 Task 可以有多个 Run。
Codex 会话
Bridge 在本机保存并尝试恢复的底层执行上下文；一条消息不等于一个新会话。

什么时候会复用

继续使用同一 Task、同一智能体，并保持 Runtime、工作区和沙箱等关键配置不变时，Bridge 会尝试恢复原 Codex 会话。第一次执行、新 Task、切换智能体、关键配置变化，或原会话被明确判定为缺失或无效时，会使用隔离的新会话。

遇到会话错误怎么办

每个本机 Codex Agent 都可以选择会话占用策略。“保留原会话”维持底层上下文并等待重试；“新建会话”只在 Bridge 明确识别到另一个客户端持有会话时生效。旧 Codex 会话不会被删除，但 ConveneWire 后续执行会切换到新的会话并重新注入当前 Task 上下文。

CODEX_SESSION_IN_USE另一个本机客户端正在持有该会话，且当前策略选择保留原绑定。可以等待后重试。

CODEX_SESSION_RESUME_FAILED恢复被拒绝，但 Bridge 无法安全判断为会话缺失。可以重试；Bridge 不会创建替代会话。

  1. 先等待 Codex Desktop 或 CLI 中相关操作结束。
  2. 仍提示占用时，完全退出持有该会话的 Desktop 或 CLI 进程。
  3. 回到原 ConveneWire Task 重试，不要为了绕过错误新建 Task 或修改工作区、沙箱。
  4. 恢复失败持续出现时，在“客户端维护”中导出脱敏诊断包再排查；不要手动删除本机会话。

关于共享 daemon

共享 App Server 是后续可评估的架构方向，不是当前 Bridge 功能。只有 Desktop 能明确连接同一个外部 daemon，并补齐生命周期、取消、审批、工作区和权限隔离后，才适合启用。
